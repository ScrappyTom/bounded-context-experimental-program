## Why this is the next interaction

E57 does not support a generic rule that semantic maintenance should simply
wait for “enough evidence.” Unsupported completion was Bluehaven-local.
Across E46, Cedar, and Bluehaven, the recurring problem was the operation
itself: every maintenance call was asked to replace one complete global
twelve-requirement state while evidence arrived a few sources at a time.

The next scout changes the information flow, not just the prompt wording:

```text
old operation
new evidence + complete prior ledger
    -> model rewrites every requirement

candidate operation
new exact evidence batch
    -> model emits only source-local evidence deltas
    -> host validates identity/scope mechanically
    -> exact task-native register updates only those source slots
```

Untouched source slots are not model-rewritten. Unsupported task requirements
remain absent rather than becoming prose obligations the model must fill.

## Whole-system question

> Under authentic prompt pressure, does a source-local semantic transform
> coupled into bounded exact task work produce more source-correct cumulative
> work, current verification, and appropriate closure than leaving the same
> evidence-to-work conversion to the ordinary actor?

The unit is the complete ingress-to-closure trajectory. This is not a contest
between two Markdown formats.

## Source-local delta contract

Each accepted delta may contain only:

- the exact source IDs and versions in its current input batch;
- one or more task requirement IDs to which those bytes bear;
- findings actually stated by those exact bytes;
- qualifications, conflicts, and observations needed to use the findings;
- explicit unknowns within that local scope; and
- exact reopen handles supplied mechanically by the host.

It may not contain:

- a complete task-state replacement;
- claims sourced from unavailable objects;
- global readiness, progress, or submission advice;
- a final decision section;
- host-inferred relevance; or
- semantic edits to records for sources absent from the call.

The carrier should be simple bounded Markdown, not a nested JSON schema. A
prospective parser may require headings and exact identifiers, while the live
validator separately enforces total tokenizer count and source allowlists.

## Bounded exact merge law

The evidence register is exact task work, not hidden model memory. Its unit of
replacement is a source/version slot:

```text
(source_id, source_version)
    -> latest accepted bounded delta for that exact object
```

A new version replaces the old slot and preserves an exact lineage handle.
Unrelated slots remain byte-identical. The host may normalize ordering and
bindings mechanically but may not combine claims semantically.

The fresh task must cap the number and size of source slots prospectively so
the complete register remains bounded for the measured horizon. This finite
scout does not establish an asymptotic lifelong note policy.

## Fresh-world requirements

Stage 0 must select a new task rather than repair Bluehaven. The world should:

- require an exact evidence register and an incrementally editable decision or

The task must not preload a gold source-to-requirement map into actor-facing
instructions. The evaluator may hold that map externally.

## Activation and cadence

The common prefix is selected by ordinary actor demand. Measurement requires:

1. materially distributed exact evidence has crossed actor boundaries;
2. a new exact result creates authentic pressure;
3. frozen first-fit relief is feasible; and
4. candidate work has not already closed the task.

L1 maintenance fires on a predeclared mechanical batch of newly externalized
exact result bodies, not when the host believes semantic maturity has arrived.
One prospective starting rule is the first three positive externalizations,
then every three additional unprocessed externalizations. Stage 0 must render
the exact packet and show that the rule preserves the actor verification tail.
The final trigger remains to be frozen from fresh-task geometry, not copied
blindly from Bluehaven.

## Required live qualification

Before a measured fork, qualify at least:

- a cold-start delta from partial exact evidence;
- a later delta over different sources while unrelated accepted slots exist;
- a replacement for a new version of an existing source;
- an actor action updating the same task-native register in W0;
- an incremental artifact mutation; and
- check, repair, recheck, and submission action shapes.

A delta fails if it cites or semantically relies on unavailable sources,
rewrites unrelated slots, exceeds its fixed budget, or introduces readiness
language. There is one attempt and no repair/retry.

## Interpretation

A positive L1 result would support the whole local policy:

```text

+ mechanical per-source merge
+ exact cumulative work
+ ordinary actor feedback loop
```

precedes ablation.

A W0 win would support direct task-native externalization over a separate
semantic provider in this regime. A loss in both arms would route from the
first new exact failure boundary rather than reopen complete-ledger tuning.
