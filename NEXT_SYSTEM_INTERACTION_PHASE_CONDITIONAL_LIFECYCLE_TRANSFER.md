# Next system interaction — phase-conditional scaffold and verification-state lifecycle transfer

Status: Orchard offline Stage 0 qualified at `444ab65`; the treatment-free
pressure screen is frozen but requires separate authorization; F0/P1 measurement
is not yet frozen or authorized

Date: 2026-08-27

## Program question

Can a fresh bounded-work system allocate different information forms to the
phases where they have positive marginal value, rather than retaining every
successful representation indefinitely?

The proposed whole-system lifecycle is:

```text
exact external world and custody
        ↓
authentic pressured evidence ingress
        ↓
temporary provenance-bound semantic scaffold
        ×
exact incremental task artifact
        ↓
construction milestone
        ↓
scaffold demotion
        +
bounded mechanical current-verification state
        ↓
actionable candidate-bound check
        ↓
bounded repair → effect uptake → current recheck
        ↓
independent readiness → correct closure
```

This is a lifecycle interaction study, not a component-isolation study. It is
not an isolated note ablation, a new register format, or another Solace
continuation.

## Why this route is selected

The active evidence now spans three linked boundaries:

1. Receipt-only evidence streaming preserved access but produced no cumulative
   work in Ceiba.
2. Solace E69 showed that anchored semantic residue, exact incremental work,
   action granularity, and transport jointly moved a pressured trajectory into
   admitted construction.
3. Solace E72 showed that retaining the same semantic stock through verification
   consumed control capacity, shortened feedback depth, and did not protect
   semantic relationships. Removing it helped, but append-only verification
   history still exhausted the context before closure.

The research target is therefore the allocation and replacement policy across
the whole lifecycle, not the intrinsic quality of one representation.

## Fresh-world requirement

Do not reuse Solace, Cedar, Bluehaven, Meridian, Aster, Ceiba, or the navigation
world as the measured task.

Stage 0 must create a fresh task with:

* at least ten materially interacting evidence objects;
* exact values, units, modalities, authorities, qualifications, and currentness
  whose relationships can be independently scored;
* authentic need for incremental work before all evidence is co-resident;
* a task-native artifact that can be updated in bounded sections or patches;
* a meaningful check/repair/recheck lifecycle;
* an independently adjudicable ready/not-ready boundary;
* enough call and response budget for evidence, construction, effect uptake,
  checking, repair, recheck, and closure;
* plausible realized pressure under the permitted ingress geometry.

Accessible-world size alone does not qualify the task.

## Compared systems

Both arms use the same exact world, task, actor, tools, first-fit relief, reopen,
incremental artifact surface, checker, resource budgets, and external readiness
adjudication.

### F0 — fixed scaffold and append-only verification history

```text
anchored semantic scaffold generated during acquisition/construction
+ exact incremental artifact
+ scaffold retained through verification
+ ordinary append-only check/effect/action chronology
```

This transfers the successful construction configuration and its E72 lifecycle
cost.

### P1 — phase-conditional scaffold plus bounded current-verification state

```text
same acquisition/construction system as F0
until the same frozen construction milestone
        ↓
scaffold moved to exact external custody
        ↓
fresh/bounded verification frame containing:
  exact current artifact and version
  latest admitted effect and delivery status
  one current candidate-bound check or explicit not-yet-checked status
  exact expected/observed validator findings
  exact handles to scaffold, evidence, and full history
        ↓
after every patch/check:
  replace stale model-facing verification state
  preserve every exact event externally
```

P1 does not semantically summarize verification history. Candidate identity,
effect binding, check currency, expected/observed structure, and exact handles
are mechanical facts.

## Common construction milestone

The phase transition must be prospectively task-derived and common to both
arms. Candidate examples include:

* all required artifact sections exist and a task-derived construction minimum
  is met;
* the actor invokes a mechanically valid `begin_verification` action;
* a frozen bounded intermediate artifact is complete.

The host may not infer that the model “seems ready.” The transition does not
authorize submission and does not assert artifact readiness.

## Actionable feedback contract

The common checker must bind findings to the exact candidate and expose:

* criterion ID;
* observed value, structure, or relation;
* frozen expected value, structure, or relation;
* exact candidate hash;
* current/stale status;
* blocking versus nonblocking disposition.

It must cover material relationships, not only concept presence. For example:

```text
unsupported:
  forty-eight samples per round
source-supported:
  current confirmatory set contains forty-eight samples
  clearance requires two complete rounds at least sixteen hours apart
```

The checker does not declare independent readiness. External evaluation remains
common and actor-invisible until the task's normal feedback contract says
otherwise.

## Replacement law in P1

After each mutation or check:

```text
old current-verification projection
        -> replacement projection
```

not:

```text
old check + patch effect + new check + patch effect + ...
```

The external ledger remains append-only and exact. Only model-facing current
verification state is replaced.

The projection must retain enough causal binding to distinguish:

* current candidate versus evaluated candidate;
* latest effect delivered versus pending;
* current check versus stale historical check;
* unresolved blocker versus repaired-but-not-rechecked claim;
* exact reopen/history handles.

## Interaction horizon

The measured horizon must continue through one of:

* correct ready submission;
* correct explicit not-ready disposition with exact blockers;
* resource exhaustion;
* invalid action budget;
* a newly observed mechanical or semantic failure boundary.

It must reserve decisions for:

1. final construction effect uptake;
2. current check;
3. targeted evidence recovery if needed;
4. bounded repair;
5. repair-effect uptake;
6. current recheck;
7. optional second repair/recheck;
8. correct closure.

No progress-state or closure-cue call is added.

## Primary outcomes

Report the outcome vector without collapsing it into one score:

* artifact relationship fidelity;
* exact effect uptake;
* current check and recheck;
* correct repair of actual defects;
* correct readiness discrimination;
* useful completion;
* semantic scaffold production and carrying cost;
* artifact mutation and transport cost;
* verification-state replacement cost;
* source reopen and induced demand;
* cache loss and wall time;
* failure migration.

## Interpretation

Possible results:

* P1 > F0 through repair/closure: phase-conditional demotion and bounded
  verification-state replacement have positive joint value in the fresh world.
* F0 > P1: the scaffold retained important meaning that the artifact/check frame
  did not preserve, or the transition disrupted continuity.
* both construct but neither verifies: checker/action or lifecycle geometry is
  still insufficient.
* both verify but close incorrectly: readiness remains the dominant boundary.
* P1 saves context but lowers quality: demotion removed economically valuable
  semantic relations.

No outcome isolates scaffold demotion from verification-state replacement.
That is intentional: the study first asks whether the complete lifecycle
allocation works. Component ablation follows only after fresh-world signal.
