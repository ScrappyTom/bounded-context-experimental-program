# Program reconciliation: what was planned, what was learned, and what remains

Date: 2026-08-22
Status: current program synthesis; mechanism-scouting phase closed

## Executive disposition

The program has enough component evidence to stop searching the current donor
trajectories for a slightly better exact layout, eviction prompt, digest format,
frontier schema, or maintenance dialogue.

The strongest earned system is smaller than the context-manager concept that
motivated the work:

```text
exact external custody
+ ordinary chronology while healthy
+ host-owned response and control reserves
+ minimum-necessary deterministic pressure relief
+ exact reopen on actor demand
+ bounded exact phase reentry when chronology becomes the burden
+ independent candidate/task/evidence-bound evaluation
```

This is an experimental incumbent, not a promoted general architecture. The
next high-value question is whether these pieces improve complete operation on
fresh tasks. If that whole method fails, the next isolated mechanism should be
selected from its observed failure boundary—not from the remaining catalog of
imaginable memory techniques.

## What was planned versus what was learned

| Original expectation or question | What the program learned | Current consequence |
|---|---|---|
| A large structural outline might be the capacity bottleneck after acquisition. | Outline demotion restored physical capacity, but the strict post-delivery behavioral fork did not exist. Later, small demotions of other old exact results solved the same delivery pressure while the outline stayed resident. | Manage the complete resident budget; do not predesignate the outline as the universal eviction target. |
| More available decisions might allow acquisition to turn into construction. | Recurrent pressure relief kept two trajectories alive for 12 decisions each, yet all 24 decisions were reads and one seed entered an exact period-three reopen loop. | Capacity opportunity and task progress are separate outcomes. |
| Oldest-first exact-result demotion might be a long-running policy. | It repeatedly prevented overflow and supported exact recovery, but produced lifecycle churn and did not preserve a stable working set. | Keep it as conservative pressure relief, not a complete workspace policy. |
| A better host-selected exact set or placement might orient the actor. | Directories, one-span focus, two-span focus, and update-slot variants moved or repeated demand rather than converging reliably. | Close fixed-layout tuning at these endpoints. |
| Exact recoverability might be enough for continuity. | Reopen handles worked operationally, but recoverability did not provide simultaneous semantic co-residency. | Treat exact custody as a safety substrate, not a cognitive working state. |
| Accumulated history could remain after result bodies were demoted. | Late audit showed 8.4–9.2K tokens of acquisition trail crowding out a relevant exact set that fit comfortably in a fresh packet. | Chronology itself has a lifecycle; bounded exact reentry is required eventually. |
| Fresh exact reentry might preserve useful work without acquisition history. | It produced a substantive mutation in one seed and preserved continuity in older code/research phase studies, but cost and success varied by domain and phase. | Retain reentry as a conditional phase mechanism, not a universal winner. |
| A bounded note or frontier might provide semantic continuity. | Freeform outputs exceeded their bounds; structured outputs exposed transport/schema failures; actor utility was never qualified for those interfaces. | Stop schema tuning. Semantic continuity remains open, not disproved. |
| A source digest might substitute for repeated raw source recovery. | A bounded digest changed behavior but induced a related-source reopen followed by the original reopen, adding cost without progress. | Digests are optional investments whose value depends on future demand, coupling, and regime. |
| A progress state might stop redundant acquisition and support closure. | It changed a reread into submission, but the unchanged artifact was a known strong partial. | Control-relative semantics have high leverage and high false-closure risk; they cannot self-authorize readiness. |
| Optional model workspace controls might let Qwen manage residency. | The actor ignored them, and the management state later became unreachable. | Hard safety and control reachability are host responsibilities. |
| A dedicated maintenance turn might fix the reachability problem and reveal useful selection. | Reachability and feasibility passed in both seeds, but managers released 6.5–7.0K tokens for deficits of 394 and 1,045, and both actors immediately requested the released source. | Dedicated mode does not by itself make Qwen a useful cache allocator. Close open-ended model-owned eviction as the current route. |
| Fewer calls, fewer reads, or earlier submission would indicate success. | The H05 correction reversed utility without changing raw behavior; premature closure looked efficient until exact candidate adjudication was reconciled. | Quality, readiness, and effect uptake must govern economics. |
| One context representation might dominate. | Value repeatedly changed with phase, co-resident evidence, candidate state, and induced future demand. | Treat the system as adaptive, path-dependent information economics, not a ranking of static memory formats. |

## Ownership split earned by the evidence

The evidence supports a conservative division of responsibility.

Host-owned mechanical responsibilities:

- exact custody, versions, hashes, and reopenability;
- prompt accounting and prospective capacity checks;
- response and maintenance/control reserves;
- minimum amount of pressure relief;
- deterministic receipt substitution and admission;
- exact current-world and phase reentry mechanics; and
- candidate/task/evidence-bound evaluation and readiness reconciliation.

Model-owned semantic responsibilities:

- ordinary task actions;
- interpretation of exact evidence;
- actual reads and reopens, which reveal current demand;
- construction, repair, and submission proposals; and
- optional semantic state only when a later experiment establishes its value and
  safety under a named trigger.

The host should not infer semantic relevance merely to choose an eviction. The
model should not be responsible for noticing or repairing a hard overflow at
the last possible token.

## Mechanism-scoping conclusion

The program is not claiming that Qwen can never manage residency, that digests
never help, or that progress state is always harmful. Those universal claims
would exceed the evidence.

The firmer operational conclusion is narrower:

> The current program should not spend more experiments on open-ended
> model-owned eviction or small host-selected exact-layout variants at the same
> donor boundaries. Their key architectural questions have been answered well
> enough for routing.

That stopping rule prevents logical uncertainty from becoming an indefinitely
extensible prompt-tuning program.
